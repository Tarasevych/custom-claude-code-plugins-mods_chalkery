# chalkery

[![CI](https://github.com/drdickgraysonjr/chalkery/actions/workflows/ci.yml/badge.svg)](https://github.com/drdickgraysonjr/chalkery/actions/workflows/ci.yml)

[English](README.md) | Українська

Chalkery — місце, де лежить крейда: дім для модифікацій Claude Code, які малюють над полем введення.

Три модифікації для Claude Code, які малюють смугу над полем введення. Працюють у терміналі й у вкладці Code настільного застосунку.

![Смуга у вкладці Code настільного застосунку: Handoff з розміром контексту, стан кешу з «Тримати теплим» і «Що далі?»](docs/band-desktop-uk.png)

![Та сама смуга в терміналі](docs/band-terminal-uk.png)

*Знімки екрана знято зі зниженою опцією `threshold`, тому Handoff світиться ще до 180k.*

| Модифікація | Що робить |
| --- | --- |
| [`handoff-relay`](plugins/handoff-relay/README.uk.md) | Кнопка Handoff запускає `/handoff`. Від 180k токенів контексту (опція `threshold`) вона підсвічується. Щойно документ передачі контексту записано, замість кнопки з'являється «Handoff створено». Модифікація приносить власний навичка `handoff`, тож кнопка працює одразу після встановлення. |
| [`cache-meter`](plugins/cache-meter/README.uk.md) | Показує, скільки ще кеш запиту лишатиметься теплим і скільки коштуватиме перекешування. «Тримати теплим» не дає кешу охолонути. Перед надсиланням в охололий великий кеш модифікація питає підтвердження. |
| [`next-steps`](plugins/next-steps/README.uk.md) | Кнопка «Що далі?» пропонує до трьох наступних запитів. Обраний запит стає чернеткою в полі введення, Enter натискаєте ви. |

Модифікації можна ставити окремо або всі разом. У будь-якому поєднанні вони складаються в одну смугу з тим самим порядком рядків: Handoff, кеш, «Що далі?».

## Вимоги

Claude Code 2.1.289 або новіший. Модифікації побудовані на function hooks, порівняно новій частині Claude Code, і перевірені на 2.1.289. Старіші версії можуть їх не завантажити: 2.1.96, наприклад, відхиляє їхні маніфести.

Версію покаже `claude --version`, оновлення — `claude update`. Настільний застосунок оновлюється сам.

## Встановлення

Спершу додайте каталог розширень:

```bash
claude plugin marketplace add drdickgraysonjr/chalkery
```

Усі три модифікації однією командою. Набір називається primaries: три модифікації, як три основні кольори.

```bash
claude plugin install primaries@chalkery
```

Або лише потрібний:

```bash
claude plugin install cache-meter@chalkery
```

У настільному застосунку те саме є в меню Plugins → Add plugin: вкладка Marketplaces, потім Add marketplace. Модифікації починають працювати з наступної сесії.

Коли виходить нова версія, спершу оновіть каталог, потім кожен встановлений модифікація:

```bash
claude plugin marketplace update chalkery
```

```bash
claude plugin update cache-meter@chalkery
```

Видалити набір: `claude plugin uninstall primaries@chalkery`. Три модифікації, які він поставив, після цього лишаються встановленими. Щоб прибрати і їх, виконайте `claude plugin prune`.

## Мова

Модифікації говорять англійською й українською. Кожен має опцію `language` зі значеннями `auto` (типово), `en` або `uk`. З `auto` модифікації беруть мову відповідей Claude з `/config`, тож одне налаштування діє на всі три. Якщо мову там не задано або модифікаціям вона невідома, вони показують англійську. Задати мову явно можна в `/config` або одразу при встановленні:

```bash
claude plugin install cache-meter@chalkery --config language=uk
```

## Навичка handoff

`handoff-relay` приносить навичка `handoff`. Він пише документ для наступної сесії в `.claude/handoffs/` у корені проєкту, а якщо CLAUDE.md проєкту називає іншу теку — туди. Передачі контексту складаються в ланцюжки: сесія, яка підхоплює документ, називається `<назва> H<N>`, і кожна фаза має свій файл. У настільному застосунку навичка ще й створює картку, що запускає наступну сесію; у терміналі друкує стартовий запит, який треба вставити. Якщо у вас уже є свій `/handoff`, кнопка запускає саме його.

## Опції next-steps

Після встановлення CLI повідомить, що частину опцій не задано. Усі вони мають значення типово, тому задавати їх не обовʼязково.

| Опція | Типово | Що робить |
| --- | --- | --- |
| `language` | `auto` | `auto`, `en` або `uk`, як описано вище |
| `minAnswerChars` | `80` | Після коротших відповідей кнопки немає |
| `suggestSkills` | `true` | Пропозиція може бути навичкою чи командою зі скісною рискою сесії |

## Якщо не працює

**`Unrecognized key: "options"` або `invalid manifest file`.** Ваш Claude Code старіший, ніж потрібно модифікаціям. Виконайте `claude update` і встановіть ще раз.

**`primaries` пише `Dependency "handoff-relay@chalkery" is not found in any configured marketplace`.** З каталогом розширень, найпевніше, усе гаразд: один із модифікацій не встановився, а набір повідомляє про це так. Встановіть цей модифікація окремо, і побачите справжню помилку:

```bash
claude plugin install handoff-relay@chalkery
```

Найчастіше це помилка старої версії, описана вище.

## Для авторів

```
.claude-plugin/marketplace.json   каталог: набір і три модифікації, кожен на своєму тегу релізу
plugins/<модифікація>/                    кожен модифікація самодостатній, ставиться окремо
plugins/<модифікація>/hooks/locales/      en.mjs і uk.mjs: усі написи, які бачить людина
plugins/handoff-relay/skills/     навичка handoff і скрипт фаз (python3, з тестами)
plugins/primaries/              набір: лише dependencies на три модифікації
shared/band.mjs                   договір спільної смуги
shared/i18n.mjs                   вибір мови за опцією language
scripts/sync-shared.sh            копіює shared/*.mjs у hooks/ кожного мода
scripts/pin-releases.sh           ставить у каталог останній тег релізу кожного мода
scripts/check.sh                  запускає всі перевірки, які робить CI
docs/                             знімки екрана для README
.github/workflows/ci.yml          CI: на кожен push і pull request, і щотижня
```

**Спільна смуга.** Порядок, у якому рушій складає хуки `ui.render` різних плагінів, не задокументований і залежить від способу встановлення. Тому модифікація не ставить свій рядок над чи під тим, що повернув `next(e)`. Він вкладає рядок у спільний стовпець `prompt-band` на своє місце: Handoff 10, кеш 20, «Що далі?» 30. Чуже, тобто рядок рушія чи мода не з цього репо, опиняється під ними. Модифікація ставлять і без сусідів, тому `band.mjs` та `i18n.mjs` лежать копіями в кожному. Правити слід `shared/`, потім запустити `scripts/sync-shared.sh`. Перевірка, що копії однакові: `scripts/sync-shared.sh --check`.

**Мови.** У коді мода немає тексту, який бачить людина: модифікація бере його з `locales/<мова>.mjs`. Нова мова — це ще один файл у кожному моді, рядок у `LOCALES` і шаблон у `shared/i18n.mjs`. Тести кожного мода перевіряють, що в усіх мовах однаковий набір ключів.

**Перевірка.** `scripts/check.sh` запускає все разом: перевіряє маніфести, проганяє тести кожного мода й тести скрипта фаз, звіряє копії спільних файлів, перевіряє версії відносно тегів релізів, перевіряє, що каталог вказує на останні теги релізів, і ставить `primaries` з каталогу в тимчасову домашню теку. CI робить те саме на кожен push і pull request на Claude Code 2.1.289, найстаршій версії, яку обіцяє цей README, і щопонеділка на найновішій; якщо щотижневий прогін упав, GitHub надсилає лист. Перевірити один модифікація:

```bash
claude plugin validate plugins/cache-meter && claude plugin test plugins/cache-meter
```

Тести смуги підставляють сусідні модифікації окремими плагінами в обох порядках. Тести мови покривають `en`, `auto` без `/config` і `auto` з українською в `/config`.

**Розробка наживо.** Щоб працювати з робочою копією, а не встановленою версією, додайте теки модифікацій у `CLAUDE_CODE_PLUGIN_DIRS` (розділювач — двокрапка). Плагін із такої теки перекриває встановлений з тією самою назвою.

**Випуск.** Підніміть `version` у `plugins/<модифікація>/.claude-plugin/plugin.json`. Без цього `claude plugin update` у колег не побачить змін, а CI впаде, якщо модифікація змінився після свого останнього тегу релізу, а версія лишилась та сама. Після злиття позначте реліз тегом із теки мода: `claude plugin tag --push` створює `<модифікація>--v<версія>`, тег, за яким рушій розв'язує версії залежностей. Потім запустіть `scripts/pin-releases.sh` і злийте зміну `marketplace.json` окремим pull request.

**Що отримують користувачі.** Кожен запис каталогу називає тег релізу і його коміт, тож `claude plugin install` і `claude plugin update` дають код релізу, а не те, що лежить у `main` між релізами. Реліз доходить до користувачів лише тоді, коли каталог вказує на його тег; доти `scripts/check.sh` падає на застарілому записі. Теги релізів на GitHub не можна пересунути чи видалити, а `main` приймає зміни лише через pull request із зеленим CI.

**Чек-лист перед релізом.** Саму смугу CI не бачить, тож перед тегом перевірте руками:

1. `scripts/check.sh` проходить.
2. Зі зміненими модифікаціями в `CLAUDE_CODE_PLUGIN_DIRS` нова сесія в терміналі показує смугу в порядку: Handoff, кеш, «Що далі?».
3. Те саме у вкладці Code настільного застосунку.
4. Handoff запускає `/handoff` і, щойно документ записано, поступається рядку «Handoff створено» і в терміналі; «Що далі?» пропонує варіанти, `/cache` показує стан кешу.
5. Якщо перемкнути `language` на `uk`, а потім на `en`, усі написи змінюють мову.
6. У кожного зміненого мода нова `version`.
