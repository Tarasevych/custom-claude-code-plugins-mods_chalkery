# chalkery

[![Безперервна перевірка](https://github.com/drdickgraysonjr/chalkery/actions/workflows/ci.yml/badge.svg)](https://github.com/drdickgraysonjr/chalkery/actions/workflows/ci.yml)

[Двомовний огляд / Tweetalig overzicht](README.md) | **Українська** | [Nederlands](LEESMIJ.nl.md)

Назва `chalkery` означає місце, де зберігають крейду: оселя для модифікацій середовища `Claude Code`, які виводять інформаційну смугу безпосередньо над полем введення запиту.

До набору входять три модифікації для `Claude Code`, що формують єдину інформаційну смугу над полем введення. Вони працюють як у терміналі, так і у вкладці коду настільного застосунку.

![Інформаційна смуга у вкладці коду настільного застосунку: передача контексту з обсягом контексту, стан проміжної пам'яті з кнопкою «Тримати теплим» і кнопка «Що далі?»](docs/band-desktop-uk.png)

![Та сама інформаційна смуга в терміналі](docs/band-terminal-uk.png)

*Знімки екрана зроблено зі зниженим значенням параметра `threshold`, тому кнопка передачі контексту підсвічується ще до досягнення 180 тисяч облікових одиниць.*

| Модифікація | Призначення |
| --- | --- |
| [`handoff-relay`](plugins/handoff-relay/ОГЛЯД.uk.md) | Кнопка передачі контексту запускає команду `/handoff`. Від 180 тисяч облікових одиниць контексту (параметр `threshold`) вона підсвічується. Щойно документ передачі контексту записано, замість кнопки відображається напис про створений документ. Модифікація містить власну навичку `handoff`, тож кнопка працює одразу після встановлення. |
| [`cache-meter`](plugins/cache-meter/ОГЛЯД.uk.md) | Показує, скільки ще проміжна пам'ять запиту лишатиметься теплою і скільки коштуватиме повторний запис у проміжну пам'ять. Кнопка «Тримати теплим» запобігає охолодженню проміжної пам'яті. Перед надсиланням повідомлення в охололу велику проміжну пам'ять модифікація запитує підтвердження. |
| [`next-steps`](plugins/next-steps/ОГЛЯД.uk.md) | Кнопка «Що далі?» пропонує до трьох наступних запитів. Обраний запит стає чернеткою в полі введення, а клавішу підтвердження натискаєте ви. |

Модифікації можна встановлювати окремо або всі разом. У будь-якому поєднанні вони складаються в одну смугу з незмінним порядком рядків: передача контексту, стан проміжної пам'яті, «Що далі?».

## Вимоги

Потрібна версія `Claude Code` 2.1.289 або новіша. Модифікації побудовано на функційних перехоплювачах — новій підсистемі `Claude Code`, перевіреній на версії 2.1.289. Старіші версії можуть відхиляти їхні описові файли.

Перевірити поточну версію можна командою `claude --version`, а оновити — командою `claude update`. Настільний застосунок оновлюється автоматично.

## Встановлення

Спершу додайте каталог модулів розширення:

```bash
claude plugin marketplace add drdickgraysonjr/chalkery
```

Усі три модифікації встановлюються однією командою. Набір називається [`primaries`](plugins/primaries/ОГЛЯД.uk.md): три модифікації, немов три основні кольори.

```bash
claude plugin install primaries@chalkery
```

Або встановіть лише потрібну модифікацію окремо:

```bash
claude plugin install cache-meter@chalkery
```

У настільному застосунку ті самі дії доступні через меню модулів розширення та додавання каталогу. Модифікації починають працювати з наступного сеансу.

Коли виходить нова версія, спершу оновіть каталог, а потім кожну встановлену модифікацію:

```bash
claude plugin marketplace update chalkery
```

```bash
claude plugin update cache-meter@chalkery
```

Щоб вилучити набір, виконайте `claude plugin uninstall primaries@chalkery`. Три модифікації, які він встановив, після цього залишаються; щоб прибрати і їх, виконайте `claude plugin prune`.

## Мова інтерфейсу

Модифікації підтримують українську та англійську мови інтерфейсу. Кожна має параметр `language` зі значеннями `auto` (типово), `en` або `uk`. За значення `auto` модифікації визначають мову відповідей із налаштувань `/config`, тож одне налаштування діє на всі три модифікації. Задати мову явно можна в `/config` або одразу під час встановлення:

```bash
claude plugin install cache-meter@chalkery --config language=uk
```

## Навичка передачі контексту (`handoff`)

Модифікація `handoff-relay` містить вбудовану навичку [`handoff`](plugins/handoff-relay/skills/handoff/SKILL.md). Вона записує підсумковий документ для наступного сеансу в теку `.claude/handoffs/` у корені проєкту, а якщо файл `CLAUDE.md` проєкту вказує іншу теку — використовує її. Передачі контексту утворюють ланцюжки: сеанс, який підхоплює документ, отримує назву `<основа> H<N>`, і кожен етап має власний файл. У настільному застосунку навичка також створює картку запуску наступного сеансу, а в терміналі виводить початковий запит для вставлення. Якщо у вас уже є власна команда `/handoff`, кнопка запускає саме її.

## Параметри `next-steps`

Після встановлення інтерфейс командного рядка може повідомити, що частину параметрів не задано. Усі вони мають типові значення, тому задавати їх вручну не обов'язково.

| Параметр | Типове значення | Призначення |
| --- | --- | --- |
| `language` | `auto` | `auto`, `en` або `uk`, як описано вище |
| `minAnswerChars` | `80` | Після коротших відповідей кнопка не відображається |
| `suggestSkills` | `true` | Пропозиція може бути навичкою або командою зі скісною рискою поточного сеансу |

## Усунення несправностей

**Повідомлення про невідомий ключ `options` або хибний файл опису.** Ваша версія `Claude Code` старіша за необхідну. Виконайте `claude update` і повторіть встановлення.

**Набір `primaries` повідомляє, що залежність не знайдено в жодному налаштованому каталозі.** Із каталогом розширень зазвичай усе гаразд: одна з модифікацій не встановилася, а набір повідомляє про це таким чином. Встановіть цю модифікацію окремо, щоб побачити справжню причину помилки:

```bash
claude plugin install handoff-relay@chalkery
```

Найчастіше причиною є застаріла версія середовища, описана вище.

## Відомості для розробників

```
.claude-plugin/marketplace.json   каталог: набір і три модифікації, прив'язані до міток випуску
plugins/<модифікація>/            кожна модифікація самодостатня і встановлюється окремо
plugins/<модифікація>/hooks/locales/  файли мовних рядків (en.mjs та uk.mjs)
plugins/handoff-relay/skills/     навичка передачі контексту та сценарій обчислення етапів (python3, із тестами)
plugins/primaries/                набір: містить лише залежності від трьох модифікацій
shared/band.mjs                   спільна узгоджена логіка інформаційної смуги
shared/i18n.mjs                   визначення мови за параметром language
scripts/sync-shared.sh            копіює shared/*.mjs у теку hooks/ кожної модифікації
scripts/pin-releases.sh           прописує в каталозі останні мітки випуску кожної модифікації
scripts/check.sh                  запускає всі перевірки безперервної інтеграції
docs/                             знімки екрана для документації
.github/workflows/ci.yml          робочий процес перевірок на кожне надсилання змін і щотижня
```

**Спільна смуга.** Порядок, у якому рушій викликає перехоплювачі `ui.render` різних модулів розширення, не задокументований і залежить від способу встановлення. Тому модифікація не ставить свій рядок просто над чи під результатом `next(e)`. Вона вкладає свій рядок у спільний стовпець `prompt-band` на визначене місце: передача контексту — `10`, проміжна пам'ять — `20`, «Що далі?» — `30`. Сторонні елементи (рядок самого рушія або модифікації з іншого джерела) розташовуються під ними. Оскільки кожну модифікацію можна встановити окремо без сусідніх, файли `band.mjs` та `i18n.mjs` скопійовано в кожну з них. Зміни слід вносити у `shared/`, після чого запускати `scripts/sync-shared.sh`. Перевірка збіжності копій виконується командою `scripts/sync-shared.sh --check`.

**Мови.** У програмному коді модифікацій немає видимих користувачеві написів: усі рядки завантажуються з `locales/<мова>.mjs`. Додавання нової мови потребує лише нового файлу в кожній модифікації, запису в `LOCALES` і зразка розпізнавання у `shared/i18n.mjs`. Перевірки кожної модифікації засвідчують однаковість набору ключів у всіх мовних файлах.

**Перевірки.** Сценарій `scripts/check.sh` запускає всі перевірки послідовно: перевіряє описові файли, виконує тести кожної модифікації та сценарію етапів, звіряє копії спільних файлів, перевіряє версії відносно міток випусків, засвідчує прив'язку каталогу до останніх міток випусків і встановлює `primaries` із каталогу в тимчасову домашню теку. Перевірити окрему модифікацію можна так:

```bash
claude plugin validate plugins/cache-meter && claude plugin test plugins/cache-meter
```

Тести смуги завантажують сусідні модифікації як окремі модулі розширення в обох порядках. Мовні тести охоплюють англійську, автоматичний вибір без `/config` та автоматичний вибір з українською мовою в `/config`.

**Розробка наживо.** Щоб працювати з локальною робочою копією замість встановленої версії, додайте теки модифікацій у змінну середовища `CLAUDE_CODE_PLUGIN_DIRS` (через двокрапку). Модуль розширення з такої теки перекриває встановлений модуль із тією самою назвою.

**Випуск нової версії.** Підніміть значення `version` у файлі `plugins/<модифікація>/.claude-plugin/plugin.json`. Без цього команда `claude plugin update` не побачить змін, а перевірка завершиться помилкою, якщо модифікація змінилася після останньої мітки випуску без підвищення версії. Після злиття створіть мітку випуску з теки модифікації: `claude plugin tag --push` створює мітку `<модифікація>--v<версія>`, за якою розв'язуються залежності. Потім запустіть `scripts/pin-releases.sh` і внесіть оновлений `marketplace.json`.

**Що отримують користувачі.** Кожен запис каталогу вказує на конкретну мітку випуску та відповідну фіксацію змін, тож `claude plugin install` і `claude plugin update` встановлюють лише перевірений випуск, а не проміжний стан гілки `main`.

**Контрольний список перед випуском.** Автоматичні перевірки не відображають візуальну смугу, тому перед створенням мітки випуску перевірте вручну:

1. Сценарій `scripts/check.sh` успішно проходить усі перевірки.
2. Із зміненими модифікаціями в `CLAUDE_CODE_PLUGIN_DIRS` новий сеанс у терміналі показує смугу в порядку: передача контексту, проміжна пам'ять, «Що далі?».
3. Те саме відображається у вкладці коду настільного застосунку.
4. Кнопка передачі контексту запускає `/handoff` і після запису документа змінюється на повідомлення про створений документ; кнопка «Що далі?» пропонує варіанти, а `/cache` показує стан проміжної пам'яті.
5. При перемиканні `language` на `uk`, а потім на `en`, усі написи змінюють мову.
6. У кожної зміненої модифікації оновлено поле `version`.
